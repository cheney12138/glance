# ADR-0016:跨屏搬窗是**原子动作**，且搬完归属立刻改变

**状态**:已接受(2026-09-22) · **触发**:用户从"效率"角度点名要的功能(候选清单里的 P2)

## 决定

在导航态里加一个动作键 **`T`**(与 `Q/W/M/F/H` 同一层):把**当前选中的那扇窗**搬到**下一块屏**,
多屏**循环**(再按一次搬回来)。三条口径:

1. **尺寸不变**(pt 原样搬)。按目标屏比例缩放读起来像"窗口变了" ✗ —— 用户要的是"挪过去" ✓
2. **落点** = 源屏上的**相对位置**等比映射(`ScreenMovePolicy.Landing.relative`);
   放不下时保证**上沿/左沿**可见。想改成"落在目标屏正中" ⇒ 只改那一个常量 ✓
   (这是**产品决定**,先用默认做出来,改起来一行 ✓ —— 见 `GlanceCore/ScreenMovePolicy.swift`)
3. **搬完立刻复枚举**:这扇窗不再归本屏(ADR-0008)⇒ 它从本屏候选集里消失 ✓;
   若它是该 App 在本屏的**最后一扇窗**,那一格也随之从环上退场 —— **这是正确行为** ✓

## 为什么它不是"新的候选集规则"(与 ADR-0008 的关系)

ADR-0008 管的是**候选集**(哪扇窗出现在哪块屏的面板上);本 ADR 管的是**一个动作**。
动作可以改变归属 —— 改变之后候选集照 ADR-0008 重新算,不含任何跨屏候选 ✗ ✓

## 否决的方案

- **跨 Space 移动**(搬到别的桌面/全屏空间):要走私有 API(`CGSMoveWorkspaceWindow` 一类),
  与 ADR-0002「私有 API 隔离 + 降级」的代价不成比例 ✗ 不做
- **拖拽搬窗**(鼠标把窗口拖到另一块屏):本来就能拖,且 ADR-0012 已否决拖拽类交互 ✗
- **要不要跟鼠标落点**:用户口径是"挪过去",不是"放到我指的地方" ⇒ 不引入指针依赖 ✓
  (指针只在本产品里做"语境屏"那件事 ✓ ADR-0001)
- **搬完把窗口激活/拉到前台**:不动焦点 —— 搬窗不该顺带改变"谁在前台" ✗

## 代价 / 已知边界

- 有些 App 会自己夹位置(最小尺寸、贴边约束)⇒ 日志同时打"请求落点"与"AX 实得的 frame" ✓,
  两者不一致时以**实得**为准(`[T33] 搬窗: … 请求 X,Y · 实得 X,Y WxH`)
- 单屏 ⇒ 没有目的地:记一行 `[T33] 只有一块屏 ⇒ 没有可搬的目的地`,什么都不做(不假装成功 ✓)
