# ADR-0016:跨屏送窗是**脱面板的独立快捷键**(默认 ⌘⇧M,可在设置里重录)

**状态**:已接受(2026-09-22,第三版) · **触发**:用户从"效率"角度点名要的功能(候选清单 P2)

> 三版的历史(留着,免得将来重开):
> ① 面板会话里的 `T`(与 Q/W/M/F/H 同一层)—— 用户否决:「**cmd t 是很多 app 的新建快捷键**」✗
> ② ⇧+双击 ⌥ 手势 —— 用户改口:「**快捷键用 cmd + shift 默认。做在设置面板里。**」✗
> ③ **本版**:一个独立注册的 Carbon 快捷键,默认 **⌘⇧M**,设置面板里可**重录** ✓

## 决定

按 **⌘⇧M**(可在设置里改)⇒ 把**当前落焦 App 的落焦窗**送到**下一块屏**(多屏循环 ⇒ 再按一次送回来)。

- 对象 = `AXFocusedWindow`(当前落焦的那扇窗)—— 与面板里选中哪一格**无关** ✓
- 目的地 = 它**现在所在屏**的下一块;单屏 ⇒ 什么都不做(记一行日志,不假装成功 ✓)
- **搬完撑满目标屏的可见区**(2026-09-22 用户口径:「移动过去之后能默认撑满整个屏幕吗, **不是全屏**」)✓
  · "撑满" = 铺满**可见区**(避开菜单栏与 Dock ✓)—— 用整块屏会把窗口塞到菜单栏底下,
    标题栏都抓不到 ✗(Quartz 里 y 越小越靠上 ✓)
  · **不是 macOS 全屏**:不进独立 Space、不播全屏动画、也不改窗口的全屏状态 ✓
  · 想回到"保持原尺寸只挪位置" ⇒ `ScreenMovePolicy.defaultPlacement = .keepSize` 一行 ✓
- 另一个档 `keepSize` + `Landing`(相对位置 / 居中)仍在纯核里,单测覆盖 ✓
- 走的是与触发键**同一套 Carbon 注册**(`RegisterEventHotKey`)⇒ 不吞键盘事件流,
  也不依赖面板开着 ✓;键位存 `moveWindow.keyCode` / `moveWindow.modifier`(与 `trigger.*` 同构 ✓),
  **出厂默认值只有一处**:`GlanceCore.TriggerConfig.moveWindowDefault` ✓
- 设置面板「触发」组里那一行是**录制式改键**(与触发键同一个交互 ✓);改完立刻重挂 ✓
  (`UserDefaults.didChangeNotification` 观察者 ⇒ 重走 `registerTrigger`)

## 为什么不是面板里的动作键(用户裁定)

第一版做成了面板会话里的 `T`(与 `Q/W/M/F/H` 同一层)。用户否决:

> 「cmd t 是很多 app 的新建快捷键, 我期望做成**脱离面板**的 —— 跟 double option 一样。
>   在**当前落焦的 app** 上使用快捷键之后, 直接移动到另一块屏幕」

⇒ 面板里的动作键只在会话期生效(那没错),但**这个需求本身就是"不想先开面板"** ✓;
而且 `⌘T`/`T` 系在被很多 App 占用 ✗ —— 做成全局热键就会把它们改掉 ✗
⇒ 结论:**独立快捷键**(默认 ⌘⇧M)—— 与面板完全无关,也不占用"新建"这类高频键 ✓
(前两版分别是 `git revert` 与改写撤回的 ✓;`ScreenMovePolicy` 这套纯核从第一版沿用 ✓)

## 为什么住在 App 层

它要同时看 **Inventory**(窗与屏归属)与 **Focus**(AX 搬窗)⇒ 放 Trigger 里就是**双向越界** ✗
(架构脚本会报 ✓)—— 与 `DoubleOptionJump` 同一条理由 ✓ ⇒ `App/ScreenScopedSwitching.swift` ✓

## 否决的方案

- **跨 Space 送窗**:要走私有 API,与 ADR-0002「私有 API 隔离 + 降级」的代价不成比例 ✗
- **拖拽送窗**:本来就能拖,且 ADR-0012 已否决拖拽类交互 ✗
- **跟鼠标落点**:这个动作不引指针依赖 ✓(指针只负责 ADR-0001 的"语境屏" ✓)
- **送完顺带激活/拉前台**:送窗不该改变"谁在前台" ✗
- **改成 ⌃+双击 ⌥ 之类**:与既有双击 ⌃/⌥ 的语义距离更远,记不住 ✗

## 代价 / 已知边界

- ⇧ 常被按着打字 ⇒ 为了不误触,判据仍是"**两次干净的 ⌥ 之间不夹别的按键**" ✓,
  且两次 ⌥ 的 ⇧ 状态必须**一致**(⇧⌥⌥ 与 ⌥⌥ 是两个手势 ✓)
- 有些 App 会自己夹尺寸/位置(最小尺寸、贴边约束)⇒ 日志同时打"请求"与"AX 实得 frame" ✓
  (`[T33] 搬窗: … 请求 X,Y WxH(含尺寸) · 实得 X,Y WxH`);**实得不达预期**会追加一行警告 ✓
- ⚠️ **AX 的设置顺序**（被实机证伪过两轮,别再"优化"它 ✗）：
  必须 **位置 → 尺寸 → 再钉一次位置** —— 因为**窗口还在源屏上时设尺寸会被源屏夹住** ✗
  ```
  搬到外接屏: 请求 0,30 1920x1050 · 实得 0,30 1728x1050   ← 宽被夹成内建屏的宽 ✗
  ```
  (第一版只改位置 ⇒ 不会撑满 ✗;第二版"先尺寸后位置" ⇒ 被源屏夹 ✗;现在是正解 ✓
   最后那次"再钉位置"是因为尺寸变化可能让系统重排/夹位置 ✓)
