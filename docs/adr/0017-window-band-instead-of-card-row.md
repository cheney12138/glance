# ADR-0017:一只 App 的窗口 = 一张卡 + 一条「芯片轨道」

- 日期:2026-10-25
- 状态:**提案**(版式已定,实现未开始)
- 相关:ADR-0014(卡片形状 vs 位置)、ADR-0013(一条环、分段呈现)

## 背景

现状:组内**每扇窗**都是一张完整的预览卡(缩略图 + 红绿灯 + 芯片),多窗口时换行成两三排。

两条实践经验把这条路走死了:

1. **非选中的预览没有意义**。为表达"非选中"先后试过压暗(0.72)、磨砂(14pt → 6pt),
   用户实评:「idea 被选中的那几个窗口一片模糊,没有任何的展示意义」「有点太丑了」。
2. **预览有成本**:非选中窗口也要起流/拍照(实测峰值 **22 条并发流 · 440 次/秒捕获**;
   35 小时里 **2748 次后台截屏** —— 系统"屏幕共享"指示常亮就是这么来的)。

## 关键约束(这决定了形状)

> **卡宽 = 窗口比例的因变量;芯片带的宽 = 标题数量的因变量。两者永远不可能相等。**

所以**任何上下堆叠(卡片在上、芯片带在下)都会被这个矛盾咬住**:用户看原型后直接否掉:
「现在这种上下的关系,我肯定不会采纳的」。

## 决定

**横向分栏:窗口左,芯片竖排在右(像目录)。**

1. **卡**:只有**选中**那扇窗有预览;宽高**严格跟随真实窗口比例**(用户口径:「实时多窄多宽就多宽」)。
2. **芯片**:沿用现有样式 —— **App 图标 + 标题 + 圆点**;选中的是**原色**,未选中的**包一层灰调**
   (图标去饱和 + 圆点变暗 + 无胶囊底)。轨道本身**无底、无边框**。
   (2026-10-25 撤回"去掉 App 图标"那条:用户要求「把那个 APP 的图标给我加上」)
3. **滚动只为"选中出视口"服务,选中本身永不滚动**(用户:「选中一个,它就停下来,很简单。
   只有当我移动到最顶部或者底部、且有多余的标签时,它才会滚动」)。
   ⚠️ 曾试过"hover 到渐隐区就滚一枚" ⇒ 死循环(hover → 列表滚 → 指针下换成另一枚 → 再 hover),
   被用户实报为「咕咕地滚」✗ 已撤。
3b. **垂直居中**:整列芯片相对**卡片高度居中**(用户 2026-10-25:「2 个、3 个的时候大概率
   撑不满卡高…还是相对卡高居中吧」;顶部对齐会让矮列表悬在半空)。装得下 ⇒ 完全不动;
   装不下 ⇒ 只有选中那枚要**出视口**时才滚(视口内换选中一动不动)。
4. **位置恒定**(用户实报:「切换到不同的卡片时…右边的芯片也会跟着移动,我不想让它移动,看久了视觉疲劳」):
   面板宽度 = **本组最宽卡 + 间距 + 轨道宽**;卡在自己的槽位里居中、轨道贴右侧 ——
   ⇒ **在一个 App 之内,芯片的位置一个像素都不动**,卡宽变化只影响它自己的槽位内部。
5. **溢出 ⇒ 整枚步进 + 有方向的遮罩**:轨道高度 = 卡高;一次 Tab = 选中移动一枚 =
   列表**滚一枚**(不按像素算"最小距离")。永不换行、永不缩字、不显示滚动条。
   **遮罩必须有**,因为轨道高与整枚芯片的高度不可能整除 ⇒ 一屏的最后一枚只会露出**一条边**
   (用户实报:「最底下这一个,它头上露出来了一点,就很丑」)。
   遮罩**有方向**:上面还有内容才渐隐顶部,下面还有内容才渐隐底部;
   整列装得下 ⇒ 两侧都不糊(16pt)。
   **轨道是无极的**(用户:「第 6 个再滚一次就回到第 1 个,而不是从第 6 个反向跳回第 1 个」):
   实现 = 芯片渲染三份、视口停在中间那份,位移跑满一份就静默对消一个周期(画面完全等价)
   ⇒ 走到底继续走就是接着往下,永不反向跳。
6. **单窗口 = 特例,暂保持现状**:卡片 + 卡片正下方的芯片(与今天一致)。
   2026-10-25 用户:「单窗口就先不处理了,还是跟现在一样放在外面吧。这个就当特例,后面再优化。
   我实在想不到什么好的表现形式。」(试过"卡内标题栏 / 素卡 / 贴边芯片",都不满意)
   (2026-10-25 三选一,用户选定 A;B=卡内标题条、C=贴边芯片均未采用)
   ⚠️ 实现时必须**彻底绕开**现有的"卡片 + 芯片上下排列"那套结构 ——
   用户:「这个形态跟现在完全是两种风格…实现的时候要完全避开当前已有的芯片卡窗口和卡片的上下排列」。
7. **托盘(环)留在下方**不变;确认/落焦语义不变。

## 后果

- **宽度矛盾消失**:轨道宽是常量,面板宽由"本组最宽卡"决定(同一 App 内恒定)。
- 非选中窗口**不再需要任何图像** ⇒ 后台保温拍照、非选中快照、磨砂烘焙三条链一起删;
  "屏幕共享"指示常亮从根上消失,唤起也不必再等快照。
- 多行卡片的"减行"动效整套退役(不再有第二排)。
- 卡片只在**自己的槽位内部**改变尺寸 ⇒ 不会带动其它元素重排。

## 否掉的方案

- **上下堆叠(卡在上 + 芯片横带在下)**:宽度矛盾无解。
- **卡片浮在选中芯片正上方**:用户:「选到哪个,就在哪个上面出现,就没有对称的美」。
- **面板宽度随当前卡宽变**:芯片会跟着左右移 —— 用户实测后明确否掉(视觉疲劳)。
- **统一卡面**:ADR-0014 已用实测否过(窄窗的图在宽卡面里两侧留白,"丑的要死")。
- **垂直居中芯片列**:用户要的是"目录"语义 —— 与卡顶对齐。
