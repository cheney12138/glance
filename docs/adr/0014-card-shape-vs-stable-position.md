# ADR-0014:卡片形状随真窗走,换组时的位置位移**接受**

- 日期:2026-09-21
- 状态:已定(用户裁定)

## 背景

托盘里的一排卡片,宽度 = min(真实窗口尺寸, 上限)(`PanelMetrics.thumbSize`),
也就是**卡片形状跟着窗口比例走**(用户多轮确认过"这是体验最好的")。

但用户实报:「换 app 的时候,卡片里的画面**移了一下**」「不是窗框移动,是里面的快照移动了」。

## 为什么这是**逻辑互斥**,不是实现问题

行是**紧排序列**:

```
卡片 k 的左缘 = Σ(卡片 0…k-1 的宽度) + 间隙 × (k-1)
```

⇒ **位置是从宽度算出来的**。于是:

| 想要的 | 等价于 | 代价 |
|---|---|---|
| 位置不动 | 每张卡**占的宽度固定**(固定槽位 / 统一卡面) | 窄卡两侧留白 |
| 形状随真窗 | 占的**宽度 = 它自己窗口的宽** | 位置必随组变 |

两者不能同时为真 —— 因为"形状"就是"宽度","位置"又是宽度的函数。

## 试过的三条路(都是用户实评否决的)

1. **固定槽位**(槽宽 = 本局最宽卡):位置完全不动 ✓,但窄卡两侧留约 40pt 空档
   ⇒ 用户:「中间这个左右这么宽是你设计的?」✗
2. **统一卡面 + 图 fit**:位置完全不动 ✓、卡与卡紧挨着 ✓,
   但窄窗的图在宽卡面里两侧留白 ⇒ 用户:「丑的要死」✗
3. **统一卡面 + 留白铺"同图模糊"**(视频播放器做法,模糊结果后台缓存):
   ⇒ 用户:「更丑了」✗

## 决定

**保留卡片形状(占宽随窗),接受换组时的位置位移。**

已做的**减痛**措施(保留):

- 行是**左锚定**(`.bottomLeading`),不是居中 ⇒ 第一张卡永远不动,
  位移只发生在"宽度变化的那张卡之后";
- 同一组内 hover:**完全不动**(宽度只与窗口有关);
- 换回同一个 app ⇒ 位置与上次一致 ⇒ 位移是**可预测**的(不是随机抖动)。

- 病例与排除过程见 `docs/live-preview-设计.md` 附录;
- 本次排查还顺带修掉两个真 bug:① 三处像素换算用了 `NSScreen.main`(面板永不成为 key
  ⇒ 双屏时取错屏的比例)⇒ 改成 `PanelScreen.scale`;② `frozenSize`/流**从不随显示配置变化重置**
