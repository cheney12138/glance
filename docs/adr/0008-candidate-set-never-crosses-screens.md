# ADR-0008:候选集永不跨屏(按屏归属是铁律)

**状态**:已采纳(2026-09-15,用户裁决)
**相关**:ADR-0001(语境屏自触发那刻起冻结)、ADR-0007(原子操作)、`CONTEXT.md`(按屏归属 / 本屏窗 / 收敛)

## 决定

一扇窗只**归**一块屏,只出现在那块屏的面板里。**永远不做**跨屏的候选集合
(不合并、不聚合、不跟随指针)。

用户原话:「不跟,你面板跟着指针走,不是打破了我们按屏幕 group by 的设计吗,
不同屏幕的 app 窗口,就只能出现在对应屏幕,这是**铁律**。」

## 背景:为什么"跟随指针"这个选项是致命的

最初的问题很朴素:指针移到另一块屏之后,面板该显示哪块屏的 App?
看起来"跟着人走"很自然。但它有两处硬伤:

1. **它把产品的根挖掉**:候选集按屏收敛(`收敛`一词的全部价值),一旦可以聚合,
   "本屏窗"就退化成"全部窗口"的一个筛选项 —— 那正是原生切换器的病。
2. **它在触摸板上会给出不确定的世界**:指针一直在动,面板会以"按下的那一刻"为准,
   同一秒的两次触发可能落在两块屏上。用户无法预测自己会看到什么。

## 后果

- 跨屏切换 = **两个原子操作**:先 `⌃⌃` 把指针送到另一块屏,再 `⌥Tab` 切(ADR-0007)。
- 新功能若涉及"另一块屏的窗口" ✗,先问它是不是在偷偷构造跨屏候选集 ✗;是的话不做。
- 每块屏的面板**独立成立**:不依赖另一块屏有没有面板、是不是刚被用过。
