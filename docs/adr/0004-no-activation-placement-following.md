# 不做「激活落点跟随」:新窗开屏位置交给 macOS 的还原记忆

曾尝试在激活无窗应用后,把"开错屏"的新窗平移到语境屏——两条路线全军覆没,功能被毙,不再做第三次尝试。

**试过的两条路与死因**:
1. **T16 轮询修正**(250ms→60ms):先看到错屏开窗,再挪。闪烁时间窗口 = 轮询间隔,60ms 下仍肉眼可感。
2. **T17 AX 诞生监听**(`kAXWindowCreatedNotification`):以为能在"诞生那一下"抢在上屏前改位置;实测通知到达时窗口已经上屏,修正仍晚于一帧,闪烁等同。

**为什么难撤销**:如果做了,它会写进每个激活路径的语义(语境屏的管辖权扩展到"别人的新窗"),且每条激活路径都要再背一台监听器。

**根上的认知**:窗口"开在哪"由 App 自己的还原记忆在**创建那一刻**决定,公共与半私有渠道(轮询/AX 通知)拿到的都是"上屏后的既成事实";真正的抢先只有 WindowServer 私有通知层(SLS notify-proc)——为一个小痛点把整条 SkyLight 通知子系统背进这个项目的圈禁区(ADR-0002),不值。
**用户原判**:"如果是跟随上一次的记忆出现在对应屏幕,那我就接受了。"——接受系统行为,不矫正。

**如果再有人想做**:第一性问题不是"怎么挪得快",而是"有没有在上屏前知道"——回答这个问题之前别动工。
