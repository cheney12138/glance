# MRU 证据降格为 App 级近似,不做窗口级严格时序

排序与首高亮的数据源只有两个:前台 App 的激活序列,和每个 App 回答的 focusedWindow。不监听全量窗口 focus 事件、不给窗口打访问时间戳。

**为什么难撤销**:排序数据形状决定枚举层与 UI 层的接口;将来想升级成窗口级严格,数据结构要重来。

**为什么有争议**:直觉上"最近访问窗口"=窗口级 MRU。但 AltTab 为这个词追求的严格性,催生了它 70% 的复杂度(注意力仲裁引擎、跨进程事件推证)——那正是本项目冻结不做清单的第一条。近似口径与真实痛场景重合:用户在意的是"切走再切回来"的跨 App 场景,App 激活序列就是正确答案;"10 分钟不跨 App、窗口内往返"的场景里,用户本来也没有"上上个窗口"的诉求。

**已知的毛边**(接受,不修):在同一 App 两窗间反复点、从未离开过该 App 时,这两窗的先后次序系统不知道,展开层按几何/枚举顺序排,不假装知道。
