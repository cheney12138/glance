# ADR-0015:策略进领域层,机制留在应用层(性能与几何的"决定"必须是纯函数)

**状态**:已采纳(2026-09-22,用户提出并裁决:「现在有很多优化渲染和计算的逻辑, 来保帧率和性能。
现在是不是都独立耦合在具体功能里。模块化, 这种 app 开发能复用 ddd 的领域思想吗」)

**相关**:ADR-0006(窗口尺寸是一局的不变量)、ADR-0007(原子操作)、ADR-0008(按屏归属)、
ADR-0014(保留形状、接受位移)、`docs/架构-领域与基础设施.md`、`docs/重构清单.md`、`docs/量尺代价表.md`

## 决定

这个仓库按**三层**分,判据只有一条问句 —— **"这是决定,还是动作?"**

| 层 | 放什么 | 规矩 | 真身(现在) |
|---|---|---|---|
| **领域**(`Packages/GlanceCore`) | **决定**:什么算一扇窗 / 环的顺序 / 落点 / 命中与几何 / 该跑哪些流 / 预热谁 / 触感与开关语义 | **纯函数、不碰框架、可单测** | `WindowTitle` `WindowTally` `DockApps` `LandingRule` `OutsideClickRule` `NativeHotkeys` `TriggerConfig` `HapticPolicy` `RingGrid`/`TrayGrid`/`CardSizing` **`SessionInvariants`** **`LivePreviewPolicy`** |
| **应用**(`Sources/Glance/Panel` 等) | **编排**:状态机、窗口生命周期、把领域决定翻译成动作 | 越薄越好 ✓ | `PanelController`(状态机 + 窗口)、`PreviewPanelView`(执行池计划) |
| **基础设施** | **动作**:SCStream、AX、NSWindow、UserDefaults、NSScreen、Haptics | 不许做判断 ✗ | `Inventory/` `Trigger/` `Panel/` 的窗口部分 |

**并且**:"一局的不变量"这类规矩**不许只写在 ADR 里**(只有人读 ✗)⇒ 必须变成**机器能断言的东西**
(`GlanceCore/SessionInvariants.swift` + 接线),违反时打日志、常态一行都不打 ✓。

**明确不做** ✗(这条和决定一样重要):
- 不做 Repository / Aggregate / 领域事件 / 事件总线那一套 ✗ —— 这里没有持久化与多团队边界,
  它们只会把"读一个决定"变成"追五层间接" ✗
- SwiftUI 的视图身份、动画、布局系统**不进领域层** ✗(它们只在应用/基础设施层)
- 不为了形式统一而抽:只有**纯 + 常改 + 曾经错过**三条都占的决定才值得抽出来 ✓

## 背景:为什么现在做这件事(不是洁癖)

2026-09-22 一天里修的两个"性能/渲染"bug,都不是"算法错了":

1. **给看不见的卡派帧**(白帧)⇒ 掉帧。规矩"只派当前显示组的帧"写在注释里 ✗
2. **换环门禁只挡一边** ⇒ "回得来、去不了"。规矩是"两侧对称" ✓,但没人**断言**它对称 ✗

再往前一天,还有一个更典型的:**窗框宽度 634 ↔ 1509 当拍跳变** ⇒ 面板看着"抖";
根因不是公式错,而是"环窗口宽度"当时是个**每拍重算的临时值** ——
不变量(**一局内它不许变**)只存在于人的脑子里 ✗

⇒ 共同点:**决定没有单一来源、也没有断言**。而决定长在 2700 行的 `PanelController`
与 `LivePreviewPool.reconcile` 里面时,既读不清也测不了 ✗。

## 后果

- **代码评审句型**:这处改动是**决定**还是**动作**?是决定 ⇒ 进 `GlanceCore` 并配单测 ✓;
  是动作 ⇒ 留在应用/基础设施层,别做判断 ✗。
- 抽出来的第一件东西(`LivePreviewPolicy`)当场就**抓出一个真 bug**:换档停掉的窗口在"起流"那一步
  仍被当成"在跑" ⇒ 选中那张换档后**没有画面** ✗(命令式版本里 `stopStream` 顺手摘了 handle,
  所以看不出来)。这就是"抽成纯函数"的真实收益,不是形式感 ✓
- 领域层变厚 = `GlanceCore` 的测试数只增不减(现 35 条,每条对着一次真事故 ✓);
  测试**跑得过快**(毫秒级)⇒ 它就是"改完立刻知道对不对"的那把尺子 ✓
- 代价(诚实说):多一层间接。当一处逻辑"只在一个地方用、半年没改过"时,
  抽出去是**净亏** ✗ ⇒ 所以判据里"常改"那一条是硬的 ✓
