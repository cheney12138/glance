# 0013 · 双环合一:逻辑一条环,呈现分段换

状态:已接受(2026-09-18,用户拍板;交互仿真验证于 `design/双环模型C实验台.html`)

## 背景

未启动 App 的到达方式演进:环尾「入口槽」(hover/点击)→ `↓`/`↑` 键 + 四指轻点(T91)。
键切换隐秘(用户原话:「下键/四指唤起未启动环太隐秘,好 App 会有引导」),为此试过的引导
形态全部被否:底部 home 条(变厚重/与窗数点阵同族而无语义)、下沉把手、一次性气泡、揭幕动效。

三条约束(用户裁定):
1. **一切功能按产品标准做** —— 发现性必须解决,不存在"自用知道就行";
2. 启动环是**低频**场景(App 启动后很少关)—— 常驻 UI 不划算;
3. 旧「右缘入口」死于 **hover 误触**:指针扫向托盘(西北路径)必经环尾,扫过即切走整个展开层。

## 候选与取舍

- **A · 两个世界 + 键切换(原状)**:发现性完全依赖教学/affordance —— 恰是已被否光的两条路。
- **B · 一条环、两段物理合并**:发现性零成本,但长条宽度 = 已启动 + 未启动,App 多时加剧
  整体缩放 —— 「托盘不替长条压尺寸」的改革不许倒退。
- **C(选定)· 逻辑一条环、呈现分段换**:Tab 的循环**包含**未启动段(主环走到底,`Tab`
  进入;走完接回主环第一格;`⇧Tab` 反向对称),屏幕上**一次只显示一段**。发现性 = 用户按
  Tab 自然遇见,零教学;无指针入口,西北误触路径整个消失;宽度不叠加,两套尺寸原样存活;
  `↓`/四指保留为直达快捷键(语义不变),`↑` 返回;落点/确认语义全部不动。

## 决策

采用 C。正式推翻两条旧裁定:
1. **2026-09-16「未启动 App 不经 Tab 到达」**——它保护的是入口槽时代的「Tab 只切已启动
   App」纯度;入口槽已死,裁定失去标的。
2. **gesture-session-spec 落地清单 #4「换环后 Tab/⇧Tab 不在未启动项里移动」**——同源,同翻。

## 后果

- Tab 到主环末尾不再直接绕回第一格:环多了一站(未启动段);⇧Tab 反向对称。
- 段内 hover 的语义 = "挪一格选中" —— 当年 hover 误触的代价从"切世界"降为一格。
- 段头「未启动的 App · ↑ 返回 / Tab 继续」只存在于未启动段(下缘 rowPadY 留白,零高度)。
- 名单为空时段不存在(Tab 照常绕回;`↓`/四指走表三芯片)。
- 行为验收表:gesture-session-spec.md 第七节(每格「一次手测 + 一行日志」)。
