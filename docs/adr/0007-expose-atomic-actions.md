# ADR-0007:暴露原子操作,不替用户做决定

**状态**:已采纳(2026-09-15,与 grill-with-docs 设计评审同轮)
**相关**:`CONTEXT.md`(原子操作 / 收敛 / 分流)、ADR-0001(语境屏)、ADR-0005(接管必须显式开启)

## 背景

设计"键盘效率"时,反复出现同一个诱惑:**把两步合成一步**。
最典型的例子是跨屏切换——指针在外接屏、目标 App 在笔记本屏,自然想提供一个
"跳到另一块屏并直接切过去"的融合键。

用户评审原话:「暴露原子操作比融合操作更开放,尽量不要替用户做决定,我们只构造方便/效率的使用方式。」
(2026-09-15)

## 决定

**每个交互只做一件事。** 便利来自**暴露**原子操作,以及让每一步都快到不假思索,
不来自替用户把第二步也做完。

跨屏切换因此定为两次原子操作:**先双击 ⌃ 把指针送过去,再 ⌥Tab 切** ——
而不是一个"移指针 + 切换"的融合键。

## 后果

1. **新功能默认不许"顺手帮你做第二步"**。想加便利,先问:这是不是把两个决定揉成了一个?
2. 已有先例的处置:**融合动作可以有,但必须是一个独立开关、且开合语义明确**
   (如"唤起即切换"`switch.advanceOnOpen`)。默认值按"默认对齐 macOS"的规则定。
3. 承认代价:两步比一步慢一点。我们赌的是"两步都零思考"胜过"一步但替你猜"。

## 否决的方案

- **融合键("跳到另一块屏并切换")**:更快,但把两个决定(去哪块屏 / 切哪个 App)绑成一个,
  用户无法只要其中一个,也无法中途改主意。
- **自动跟随指针屏切换**(指针移过去就自动把面板也搬过去):更隐蔽地替用户做决定,
  而且会让"语境屏"这个产品的根出现例外(ADR-0001)。
