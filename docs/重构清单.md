# 重构清单（趁代码还不多）

> 目标两条：**① 所有"设计入口"（外观/手感/开关/量尺）都收成可枚举、可命名、可检查的一处**；
> **② 可复用的东西（布局数学、取帧管道、缓存、手势账本）从视图/控制器里拆出来，能单测**。
>
> 规矩（每次改都适用）：**一次只动一条** → 编译 → 看结果；**键名/语义/视觉常量值一个字不改**；
> 每条自己一个提交；做完在下面打勾并写一行"实测/验收"。

## 清单（按"风险低、收益高"排序，一条一提交）

### 1. `PanelMetrics.pitch` —— 一个属性一个源
- **现状**：`icon + iconGap` 在 4 个文件里手算 **12 次**（格宽/命中测试/悬停索引/托底位移）。
- **做法**：`PanelMetrics` 加 `static var pitch: CGFloat { icon + iconGap }`，12 处全部改引用；`PanelController` 里重复声明的 `pitch` 也删掉。
- **验收**：数值不变（`pitch` 与手算恒等）；编译通过；环/托盘观感零变化。
- **风险**：极低（纯改名）。

### 2. 开关键名清单 `Keys.swift`（**字符串一个字不改**）
- **现状**：50 处裸 `UserDefaults.standard.bool/integer/string(forKey: "xxx")`。打错一个字 ⇒ 静默失效，且没有任何检查。
- **做法**：新增 `enum K`（或 `Keys`）集中声明**全部**键名字符串常量（`static let livePreviewTier = "live.previewTier"` …），调用点改成 `K.livePreviewTier`。
- **纪律**：**键名一个字不改**（用户已有配置不丢）；**顺带提供"没写过 vs 写成 false"的区分入口**（`object(forKey:) == nil`）。
- **验收**：`grep -o 'forKey: "[^"]*"'` 的**键集合**与改前逐字相同（脚本对比）；运行后设置面板行为不变。
- **风险**：低（机械化，但必须用脚本核对键集合）。

### 3. `DebugFlags` —— 9 个调试开关收一处
- **现状**：`debug.trace` / `debug.screenProbe` / `debug.dumpSources` / `debug.hzProbe` … 散落，且**重诊断没有统一开关**。
- **做法**：`enum DebugFlags { static var trace / screenProbe / dumpSources / … }`；重诊断（上屏像素探针等）**默认关**并集中在一处文档化。
- **验收**：`grep '"debug\.'` 只剩 `DebugFlags.swift` 一处；默认全关 ⇒ 日志零噪声。
- **风险**：低。

### 4. 布局数学搬进 `GlanceCore` + 单测（**最大的一笔**）
- **现状**：卡片尺寸（`min(真窗, 上限)`）、行宽、托盘几何（`TrayGeometry`）、质心/卡位、命中测试索引，全都长在 `PanelController` 里，**零测试**。
- **做法**：纯函数搬进 `Packages/GlanceCore`：`CardSizing`、`TrayLayout`、`RingLayout`（格距/索引/托底位移）；`GlanceCoreTests` 补用例（含"形状随窗 ⇒ 位置必变"的断言）。
- **验收**：`swift test` 通过；同一输入下与改前**数值逐位相同**；`PanelController` 行数明显下降。
- **风险**：中（搬逻辑，需逐条对拍）。

### 5. 图片缓存合并
- **现状**：`AppIconCache`（pid）/ `CardImageCache`（wid+size）/ `SeatImageCache`（wid+size）三个手写 `NSLock + [K: NSImage]`。
- **做法**：`final class ImageCache<Key: Hashable>`（单一实现 + 三个实例）；`reset()` 统一（显示配置变化时清）。
- **验收**：三处行为不变；`reset` 仍被 `screenConfigChanged()` 调到。
- **风险**：低。

### 6. `WindowCapture` 从 `LivePreviewPool` 拆出
- **现状**：池同时管 ①SCStream 管道（配置/起停/首帧/像素规格）②帧盒分发 ③预热范围 ④帧率档位 ⇒ 一个类四件事，且"可变账本必须单队列"那条纪律无处安放。
- **做法**：拆 `WindowCapture`（一扇窗一条流：start/stop/onFrame，对应 DockDoor 的 `WindowLiveCapture`）；`LivePreviewPool` 只做编排（谁在采、预热、档位、屏幕变化自愈）。
- **验收**：`[直播]` 日志序列与改前一致（起流/首帧/停流条数与理由）；崩溃栈重现路径不再存在（账本单队列）。
- **风险**：中高（live 是热路径）——独立提交，出问题整条回退。

### 7. `PanelScreen` 可变全局 → 显式传参
- **现状**：`enum PanelScreen { static var scale }`（ADR-0008 的"按屏归属"）是可变全局状态，谁都能读写。
- **做法**：改成"控制器算好、随 `showPanel(context)` 显式传给取帧/缩放/模糊三处"的**纯值**；要保底再留一个只读访问器。
- **验收**：三处像素规格仍与本屏一致；`grep NSScreen.main` 进一步下降。
- **风险**：中（要顺三条取数路径）。

### 8. 量尺统一门面 `Trace`
- **现状**：`[窗框]/[托盘分段]/[键账]/[卡尺寸]/[悬停拍]/[对位]/[屏]/[卡变]/[尺子]` 各写各的 `if debug`；重探针（上屏像素量尺）会**改变被测物**（已犯过一次）。
- **做法**：一个门面 + 一个"量尺档"枚举（`off / 常态 / 全量`），所有量尺走它；重诊断**单独开关 + 默认关**；量尺名字集中登记。
- **验收**：默认零噪声；`debug.trace=1` 下能看到需要的全部；重探针仍可单独开。
- **风险**：低（只动日志）。

### 9. `PanelController` 分层拆解
- **现状**：2702 行，同时管窗口生命周期、托盘几何、环、hover、账本、日志。
- **做法**：按职责拆 `RingController`（环/hover/索引）、`TrayController`（托盘窗口/几何/对齐）、`PreviewOrchestrator`（live 编排），`PanelController` 只做协调；配合第 4 条把数学搬走。
- **验收**：行数显著下降；`Tools/check-architecture.swift` 补规则（**UI 层禁止裸 `UserDefaults` / 裸 `NSScreen.main` / 裸魔数**）并通过。
- **风险**：高（面大）——放最后，前面几条都是在为它铺路。

### 10. 触发层拆解（`HotkeyTap` 1129 行）
- **现状**：按键账本（含卡死自愈）、修饰键门禁、手势位移判据、动作键匹配全在一个类。
- **做法**：拆 `PressLedger`（账本 + `stuckLedgerAfter` 自愈）、`GestureDetector`（位移/时序）、`ChordMatcher`（⌘ 动作键全匹配）；纯逻辑进 `GlanceCore` 并可单测。
- **验收**：触发行为逐条与改前一致（含"账本卡死自愈"用例）；新增单测覆盖门禁与判据。
- **风险**：中。

## 明确"不做"（避免重构顺手改设计 ✗）

- ❌ 不改任何键名、不改任何视觉常量值、不改任何文案。
- ❌ 不动"玻璃冻结"、"形状随窗口（ADR-0014）"、"归属按操作对象（ADR-0009）"这些已裁定的事。
- ❌ 不为"好看"新增抽象层；能一行改掉的，不建协议。
