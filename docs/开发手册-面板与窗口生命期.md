## 一、核心心智模型：为什么 Glance 的残帧总是“坦克形透穿”？

Glance 的切换面板由两扇无边框 `.popUpMenu` 级 `NSPanel` 拼接成“坦克”轮廓：
- 上半凸起：预览托盘 `previewPanel`（[PanelTrayWindow.swift](file:///Users/qianyuchen/work/glance/Sources/Glance/Panel/PanelTrayWindow.swift)）
- 下半长条：应用环 `panel`（[PanelController.swift](file:///Users/qianyuchen/work/glance/Sources/Glance/Panel/PanelController.swift)）

两扇窗都采用 `.clear` 风格的 `NSGlassEffectView`（[PanelGlass.swift](file:///Users/qianyuchen/work/glance/Sources/Glance/Design/PanelGlass.swift)），会直接折射/采样面板背后屏幕区域的像素。一旦出现下面两种情况之一：
1. **面板收场后又被异步回调拉回 `alphaValue = 1` / 重新上屏**（此时 `groups` 已清或内容透明）；
2. **`orderOut(nil)` 尚未刷新进 WindowServer 就紧接着把系统焦点切到了下一个 App**；

屏幕上就会留下一块**停在最顶层、内容为空/旧图、玻璃层却冻着上一个 App（或 Glance 设置窗）对应屏幕区域像素**的“坦克形状残帧”。

## 二、写功能 / Review 必查 5 条红线

### 红线 1：异步回到主线程后，严禁只信 `isVisible`，必须校验“局号 `beginGeneration` + `isVisible`”
- **典型场景**：`Task.detached` 后台枚举、延后 1 拍的 `DispatchQueue.main.async`、8ms 步进动画、防抖定时器。
- **为什么危险**：快速 `⌘Tab` 闪切（实测 60–130ms）时，本局在后台枚举完成前就已经 `confirmSelection() -> dismiss()` 关窗；甚至可能在短短几十毫秒内又开启了下一局。
- **正确姿势**：
  - 异步出发前捕获 `let gen = beginGeneration`；
  - 回到主线程第一行写 `guard self.isVisible, gen == self.beginGeneration else { return }`（如果是在 `finishBegin` 前执行，则校验 `!self.isVisible && gen == self.beginGeneration`）。

### 红线 2：早退分支里绝对不能“顺手恢复可见性 / `alphaValue = 1`”
- **反例（历史事故）**：`guard isVisible, w.isVisible else { w.alphaValue = 1; return }`。
- **后果**：动画还没跑完用户就松手退场，`teardownPanel` 刚把窗口压到 `alphaValue = 0` 并 `orderOut(nil)`，下一帧定时器就走早退分支把窗口重新写回 `alphaValue = 1`。
- **正确姿势**：所有淡入/显隐步进在检测到会话已结束时**直接 `return`**，任何清理和状态归位只留在 `teardownPanel` 里。

### 红线 3：关窗与跨进程切焦点紧挨着执行时，必须同步 `CATransaction.flush()`
- **典型场景**：`confirmSelection()` 确认选中 → `dismiss()` → `WindowFocuser.focus(...)` 激活目标 App（尤其当刚从 Glance 自家设置窗/引导页切换出去时）。
- **正确姿势**：
  - `teardownPanel` 内先用 `CATransaction.begin()` + `CATransaction.setDisableActions(true)` 将两扇窗置 `alphaValue = 0` 并 `orderOut(nil)`，再 `CATransaction.commit(); CATransaction.flush()`；
  - 最后才调用 `WindowFocuser.focus` 移交系统激活态，避免 WindowServer 未及撤窗就先切换底层窗，把旧帧背景冻进屏幕。

### 红线 4：透明内容 + `.clear` 玻璃的同步门禁
- 改动 `PanelView` / `PreviewPanelView` 的 `.opacity(...)`、`groups = []`、`entryFadeProgress` 时记住：
  - 外层窗口不可见时，内容变透明用户看不见；
  - 外层窗口若还停留在台上（哪怕只有 1–2 帧），内容层一透明，`.clear` 玻璃直接把身后窗口的像素当成前景框亮出来。
- 开局首帧必须先让两扇窗在 `alphaValue = 0` 下完成 `flushPanelBackingStores(includeTray:)`，再分步渐入；退场则必须反向先 `alpha = 0` + `orderOut` + `flush`，再清空 SwiftUI 动画状态。

### 红线 5：自家非面板窗与窗口状态变更要驱动缓存同步，不靠猜
- **自家窗口**：Glance 自己的设置窗、快速上手引导页、快捷键速查窗也是 `NSWindow`（非 `GlancePanel`），打开或关闭会改变屏幕上下文与前景窗，需经生命周期通知触发 `refreshStaleListSoon()`。
- **最小化窗口**：全部窗口最小化时最后一个占位保持原位、不消失不跳位；所有最小化卡片只展示 App Logo 占位，**严禁对 `isMinimized` 窗口启动 SCStream live 流或预填残存快照帧**。

## 三、改动涉及本手册领域后的自检步骤（本仓规范）

1. **静态架构守卫**：
   ```sh
   swift -module-cache-path /tmp/glance-mc Tools/check-architecture.swift
   ```
2. **纯核单测与 App 构建**：
   ```sh
   swift test --package-path Packages/GlanceCore
   xcodebuild -scheme Glance -configuration Debug build
   ```
3. **日志复盘口径**（遇到“残帧 / 面板滞留”时先查 `~/Library/Logs/Glance/trace.log`）：
   - 先看 `[窗口] 收场后 环/托 isVisible=false alpha=0.0` 之后，同一毫秒段内是否紧跟着 `[T8] 枚举到达` 或 `[托盘] 上屏`；若有，说明又有某条异步链漏了 `beginGeneration + isVisible` 门禁。
   - 若正在工作且本机跑着正式/调试版 Glance，按 [AGENTS.md](../AGENTS.md) 约定**只编译不跑 `Tools/run.sh`**，由用户实机重启验收。
