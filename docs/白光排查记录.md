## 五、结论（2026-09-17 晚）:**收掉了 —— 用"绕开那一帧"的写法,不是靠找出凶手**

**改法**(`PanelController.showPanel`，见那里的注释):

```swift
panel.alphaValue = 0                 // 先以透明上屏:合成器会把这一帧真的合成一次(含材质)
…布局/绘制/orderFrontRegardless…
DispatchQueue.main.async {           // 下一拍(~16ms)才拉到 1
    panel.alphaValue = 1
    probeShownFrames(panel)          // 连拍挪到这里:拍"第一次被看见的那几帧"
}
```

用户实机确认:**不闪了**(新进程的第一次唤起)。

### 为什么是"绕开"而不是"修好"

- **根因到今天也没定死** ✗：位图探针三次都拿不到"上屏那一帧"(上屏前内容还没提交进图层)，
  动态色被量死、`glassLip` 未绘制、`sheen` 是关的、发布版对照把范围压到 `v0.1.2..811a26f` 的 6 个文件
  —— 但**没等到"哪一行"**。
- 而**"让用户看到的第一帧一定是合成过的"** 这条不需要知道凶手是谁 ✓：
  不管那一帧缺的是内容还是材质,先合成一次再让人看见,白光就没有立足之地。
- ⚠️ **这不是入场动效**：0→1 只隔一拍(~16ms),用户感知不到;与"面板要已经在"不冲突。
- ⚠️ **别为了"省一行"去动它**：它现在是"刚好"的状态。真要动,先读本节与第一节的事实清单。
