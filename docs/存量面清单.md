过了一遍当天的病例，根因**不是"耦合"**，而是三类：

| 类别 | 今天的实例 | 真正的修法 |
|---|---|---|
| **A 规则只写在注释里**，没人强制 | "先记后摘"漏用在记号上 ✗ · 撞进"复核期(诈尸)" ✗ | 规则 ⇒ 纯函数 / 单一入口 / 单测 |
| **B 同一件事有两条应用路径** | `finishBegin` 直接赋值 vs `applyRefreshed`（"记号不消失"的真因 ✓） | 合并成**唯一入口** |
| **C 验证吞吐**：只能靠真机人工试 | 你"不敢发版、要压一天半天" | 自动化回归门 + 明确的真机验收清单 |

> ★ **重构不是万能的**：今天 5 个病例，`PanelController` 那 3049 行**一块都挡不住**（那些 bug 在
> 语义/寿命/路径上，不在耦合上 ✓）。所以顺序是：**先让规则可执行** ⇒ 再**切片**拆大件 ✓。

## 二、今天新增/重申的规则（每条都要能自检）

5. **寿命必须写进名字**：常驻的记忆 vs 只活一局的口径**分开存** ✓
   （病例：`minimizedPIDs` 一份数据当两种规则用 ⇒ 先"不消失"✗ 再"拉不起窗"✗，连修两轮 ✓）
   → 自检：每加一张表/集合，注释里必须写"它活多久、谁清它" ✓
6. **先记后做（乐观 + 回滚）**：动作用 AX 这类**同步跨进程调用**时，界面状态先记、失败再回滚 ✓
   （病例：把"记下已收纳"写在 AX 之后 ⇒ 图要等目标 App 缩完才变灰 ✗）
   → 自检：每个 destructive 分支都要有 **记号 → 动作 → 失败回滚** 三步可见 ✓
7. **复核期不许当真**：`purgedWIDs`（0.9s）内的窗，是"系统还没落定"的**诈尸** ✓
   （病例：我的自愈剪枝拿它当"窗回来了" ⇒ 记号一闪就没 ✗）
   → 自检：任何"读列表判断真相"的新代码，先问一句**要不要避开复核期** ✓
8. **不要用透明度表达"退后"**（用户实报"见骨头"✗）：要"退半步"用**光**（灰/压暗），不用 alpha ✓
   → 自检：改动涉及 `opacity` 时，对照图必须把"后面还有东西"画出来 ✓
   （我上一版画在纯色底上 ⇒ 测不出 ✗ —— **量具必须含真实现场** ✓）
9. **两处状态不许混用一个源**：视觉记号（常驻）≠ 行为守卫（单局）· 屏顺序口径唯一（`DisplayOrder`）✓
10. **日志预算**：常态 ≤2 行 / 重型默认关 + 开机自报代价 ✓（`DebugFlags.reportHeavySwitchesIfNeeded`）。
11. **键纪律**：键名只在 `Keys.swift` ✓ 出厂默认值只在 `Keys.KeyDefaults` ✓ 设置行不绑 `debug.*` ✓
    → 新加的可试档位要**能区分"没写过"与"写成 0"** ✓（`object(forKey:) ?? 默认` ✓）
12. **真机纪律**：用户在工作 ⇒ 不跑 `Tools/run.sh`、不注入 HID、不抓屏 ✓
