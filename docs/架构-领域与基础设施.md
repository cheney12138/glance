# 架构:领域与基础设施(以及"性能策略住在哪")

> 2026-09-22 立。起因是用户的问题:「现在有很多优化渲染和计算的逻辑, 来保帧率和性能。
> 现在是不是都独立耦合在具体功能里。模块化, 这种 app 开发能复用 ddd 的领域思想吗」。
> 决定见 **ADR-0015**。这一页是**地图**(改代码时先看这里,别猜 ✓)。

## 一句话判据

**"这是决定,还是动作?"** —— 决定进 `GlanceCore`(纯、可测);动作留应用/基础设施层 ✓

## 现状地图(真身,不是理想)

```
Packages/GlanceCore/Sources/GlanceCore/          ← 领域层(纯逻辑,不 import AppKit 功能框架)
  WindowTitle.swift            窗口标题怎么缩短、什么算"同一扇窗"
  WindowTally.swift            无窗/有窗应用怎么算(计数)
  DockApps.swift               Dock 常驻应用名单
  LandingRule.swift            唤起初落点(承接上次选中 / 回到主屏)

  LivePreviewPolicy.swift      ★ 该跑哪些流、各几 fps、何时停(纯函数)

  Panel/PanelView.swift            视图:环、卡、托底(视觉决定在这里,但几何数从 Core 来 ✓)
  Panel/PuckView.swift             托底(单独成文件:改它不用翻 500 行视图 ✓)
  Inventory/                       基础设施:AX 枚举 / 快照 / 预热

  App/Keys.swift · DebugFlags.swift  全部配置键名 / 全部调试开关(单一来源 ✓)

```

## "保帧率/省算力"的那些机制,现在住在哪

| 机制 | 真身 | 属于 | 它的**决定**在哪 |
|---|---|---|---|
| 分档 fps(选中 10 / 其余 5) | `PreviewPanelView` 执行 | 基础设施 | **`LivePreviewPolicy`** ✓ |
| keepAlive 5s(换回来是热的) | 同上 | 基础设施 | **`LivePreviewPolicy`** ✓ |
| 起流错峰 40ms | 同上 | 基础设施 | **`LivePreviewPolicy`**(给顺序)✓ |
| 起流挪出 hover 那拍(150ms) | `LivePreviewPool.sync` | 基础设施 | 调度:`allowStart` 语义在策略里 ✓ |
| 只派"当前显示组"的帧 | `ingest` 的 `guard wanted.contains` | 基础设施 | **`SessionInvariants.streamViolations`** 断言它 ✓ |
| 三张图缓存(`CardImageCache`/`SeatImageCache`/`AppIconCache`) | `Panel/` · `Design/` | 基础设施 | 缓存键与失效规则(=决定)还没抽 ✗ → 重构清单 5 |
| 预热当前组(开面板前拍好) | `Inventory/Snapshotter` · `ThumbnailRefresher` · `PanelController` | 基础设施 | **散在三处 ✗** → 待抽 `PrewarmPolicy`(见下) |
| 一局内窗框尺寸不变 | `PanelController.paddedSize`/`setFrameIfNeeded` | 应用 | **`SessionInvariants.violations`** 断言它 ✓ |
| 环窗口宽度 = 两环更宽者 | `PanelController.ringWindowWidth()` | 应用 | 同上(同样的断言 ✓) |
| 命中与托盘几何 | `PanelController` 调用 `TrayGeometry`/`RingGrid` | 领域 | **`Layout/`** ✓ |
| 动效总闸(减弱动态效果/禁用动画) | `Design/PanelMotion.swift` | 领域(策略)+ 基础设施(执行) | `MotionPolicy`(纯判断 ✓) |

⇒ 结论:**机制基本都在对的地方**(有独立类型 ✓),**过去黏住的是"决定"** ——
现在两个最热、最常改、错过一次的决定已经搬进领域层 ✓

## 改一处代码之前,先问三句

1. **它是决定还是动作?** 决定 ⇒ `GlanceCore` + 一条单测(写上"为什么"= 哪次事故 ✓)
2. **它是不是"一局的不变量"?**(尺寸 / 归属 / 一窗一流 / 一窗一帧)⇒
   加进 `SessionInvariants` 一并接线,**别只写注释** ✗
3. **它是量具吗?** ⇒ 见 `docs/量尺代价表.md`:常态 ≤2 行、重型必须独立开关 + 默认关 + 开机自报代价 ✓

## 反面教材(明确不做 ✗)

- 不建 Repository / Aggregate / 事件总线 / 依赖注入容器 ✗ —— 没有持久化、没有多团队边界,
  只会把"读一个决定"变成"追五层间接"
- 不把 SwiftUI 视图身份 / 动画 / 布局系统搬进领域层 ✗
- 不因为"三层好看"而抽:一条判据要**纯 + 常改 + 曾经错过**三条都占才值得 ✓
  (反例:某个只在角落用一次、半年没动过的 `if` ⇒ 留着,别抽 ✗)
