# Pattern:贴身拖拽源浮窗(anchor-following drag-source overlay)

> 2026-11-14 从 PermissionDragPanel.swift 的实现与病例沉淀。需求场景:App 需要用户去
> 系统设置手动授权(TCC 权限/登录项/辅助功能等)时,给用户一枚"能拖进权限列表"的图标。

## 一句话描述(需求层)

**贴身拖拽源浮窗**:在系统设置窗口的固定角落贴一枚不抢焦点的浮层,浮层上提供一枚
**可拖拽的 App 图标**——用户按住它拖进系统设置的权限列表,系统弹原生接住提示,松手即完成
添加。浮层跟随设置窗口的移动/最小化/关闭而跟随/消失,授权完成后自动收走。

## 底层原理

TCC 权限列表只接受 `.app` 文件拖放,而**拖拽得有源头**——自己的 App 够不着那个列表,
所以造一枚"Finder 同款负载的可拖图标",把它递到用户手边。

## 实现要点清单

### 窗体
- NSPanel,styleMask = `[.borderless, .nonactivatingPanel]`,level = `.floating`
- collectionBehavior = `[.canJoinAllSpaces, .fullScreenAuxiliary]`
- `hidesOnDeactivate = false`(它是"设置的贴身助手",不随宿主 App 失活消失)
- ⚠️ `isMovableByWindowBackground` 必须关——开了它 mouseDown 阶段整窗被拖走,
  SwiftUI `.onDrag` 根本接不到手势(2026-11-05 病例:「拖图标整个窗口都在跑」)

### 锚定跟随
- 100ms Timer tick(RunLoop `.common` mode)
- 用 `CGWindowListCopyWindowInfo` 找目标进程 **layer-0 最大在屏窗**的 bounds
  (NSRunningApplication 拿不到窗口列表),CG 坐标换算成 AppKit 坐标再摆
- 贴角规则:目标窗右下角内侧(右距 12 / 下距 16),夹进屏幕 `visibleFrame`
- 目标窗最小化/切 Space → 跟着藏;进程退出 → 等 5s 后收
  (**孤儿浮层比没有浮层更糟**)

### 拖拽源(最容易翻车的一层)
- ⚠️ 必须用 AppKit 原生拖拽:`NSPasteboard(name: .drag)` + `writeObjects([NSURL])`
  + `NSDraggingItem` + `beginDraggingSession`
- ⚠️ SwiftUI `.onDrag` 的 NSItemProvider 负载系统设置**不认**(2026-11-09 v2 病例:
  拖进列表「什么都没发生」)——负载必须与 Finder 逐字等价(**Finder 能进,这个就能进**)
- `beginDraggingSession` 的 source 必须是持久代理(单例 `NSDraggingSource`),
  会话期间不能释放
- 热区 = 图标本身(视觉 = 可拖范围,所见即可拖);拖拽影像 = 48pt 图标热点居中;
  位移 ≥5pt 才起拖(区分点击)
- ⚠️ 不要用 `isEnabled = false` 隔离事件——NSImageView 会把图画成淡化态(2026-11-09 v4 病例);
  事件隔离改 `hitTest` 拦截

### 生命周期
- 授权完成 → 自动收
- ⚠️ 拖拽进行中**冻结一切重定位与消失**(SwiftUI onDrag 无结束回调,
  探测 `NSEvent.pressedMouseButtons & 1` 代替)——拖一半浮层跑了 = 灾难
