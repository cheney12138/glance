# 托盘与环:两条**独立**的比例(待做)

> 2026-10-13 用户裁定。**这不是重构,是修一个耦合**:本局比例被托盘牵着走 ✗
> 起因:用户实报「6-1 之后错位」「双排时芯片贴着环」,我两次动手都被这条耦合带歪 ✗

## 用户口径(原话)

```
「卡片本来就可以有自己的比例, 环和卡片都是触发了超限之后, 才开始自适应缩小的」
「动态缩放的应该也只是预览托盘的尺寸… 大了就缩小, 窗口减少了就放大,
  变化的始终是容器的宽和高, 你给一个固定的上下边距让它在这个尺寸里自己计算」
```

⇒ 两条独立的尺子:
- **环**:只有"环自己装不下"(长条超宽)才缩 ✓(现有规则 ✓ 不动)
- **托盘**:只有"托盘自己装不下"(超出可用宽/高)才缩 ✓;窗数少了就放大回来 ✓
- **绝不互相牵** ✗

## 现状(病灶)

`Sources/Glance/Panel/PanelController.swift` `applySessionScaleCap`(约 938 行):

```swift
for g in groups where !g.windows.isEmpty {
    let fit = trayFitScale(aspects: g.windows.map(\.aspect)).scale
    cap = min(cap, fit)          // ← 就是这一行:托盘把整局比例(=环的尺寸)一起收紧了 ✗
    ...
}
PanelMetrics.sessionCap = cap
```

后果(用户两次实拍):把托盘的呼吸加大 ⇒ **环也缩小** ✗;托盘双排 ⇒ 整局比例被收紧 ✗。

## 要做的事(四处必须**同时**落地,单独改任何一处都会更糟 ✗)

1. **去掉耦合**:`cap = min(cap, fit)` 整段删掉 ⇒ `sessionCap` 只由**环自己**的长条宽度定 ✓
   (该函数末尾那行 `[尺寸] 固定 x% · 本局 y% … 托盘最挤 N 窗` 的诊断保留,改为两条尺子都报 ✓)
2. **给托盘自己的比例**:新增 `PanelMetrics.trayScale`(= `TrayScalePolicy` 纯函数,可单测 ✓):
   ```
   trayScale = min(1, 可用宽 / 一行排满时的宽, 可用高 / 内容高)      // 只缩不放 ✗(超限才缩 ✓)
   ```
   可用区 = `contextScreen.visibleFrame − margin`;高度要扣掉"环占的那一段 + 固定上下边距" ✓
3. **卡片尺寸改读 `trayScale`**:`PanelMetrics.thumbSize/thumbWidth`(卡片盒)与
   `PreviewPanelView`/`pool` 喂给 SCStream 的**像素盒**必须**同时**改 ⇒ ADR-0014
   「同一把尺子」不破 ✓(破的只是"卡片比例 = 环比例"这一条 ⇒ 补一条 ADR 记账 ✓)
4. **间距**:容器与环之间给**固定上下边距** ✓;内容在这块尺寸里自己算(几行几列、居中 ✓)
   —— 不再靠"容器比内容高出来的那截"当间距(那正是"双排贴着环"的成因 ✗)

## 判据(做完怎么算对)

```
· 6 窗(双排)⇒ 环尺寸**不变** ✓;托盘比超限时自己缩 ⇒ 芯片到环的距离 = 单排那档 ✓
· 1 窗 ⇒ 托盘按内容大小(大回来 ✓),环仍不变 ✓
· 关一扇(6-1)⇒ 一行居中 ✓,不溢出 ✓,环不变 ✓
· 长条(App 很多)⇒ 环照旧自己缩到装得下 ✓(那条规则不动 ✓)
· 卡片盒与抓屏像素盒**同源**(ADR-0014 ✓):换源不重排(用 `[尺子]` 那行核对 ✓)
```
