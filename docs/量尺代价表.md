> 起因：**同一个教训犯过两次** —— 量具把被测物改变了 ✗。
> 这份表的作用：**加量尺之前先查这里的代价**；重型量尺必须默认关、必须开机自报、用完必须关。

| 时间 | 量具 | 症状 | 实测 |
|---|---|---|---|
| 2026-09-21 | `debug.screenProbe`（逐帧读回屏幕像素） | 我们量到的"卡顿"其实是**探针自己** | 一开就产出 **70–190ms** 长帧 |
| 2026-09-21 | `debug.dumpSources`（每次 hover 导图到桌面） | 用户报「又发现掉帧了」 | 每次 hover 写 1–2 张 PNG；**max 帧 45.4ms → 关掉后 28–37ms** |

⇒ 第二次是**我把它留在 ON 上**（上轮实验后忘了关）✗。所以现在：
**重型开关开机自报**（`DebugFlags.reportHeavySwitchesIfNeeded()` 在 `GlanceApp.init` 里跑），
常态（全关）一行都不打；开着就大声报，并把**代价写在那一行里**。

## 量尺分四档

| 档 | 门禁 | 常态成本 | 例子 |
|---|---|---|---|
| **零档：常态** | 无 | 无 | — |
| **一档：轻量常态** | `debug.trace` | 每次调用 ≤2 行 | `[直播]` 起/停/首帧、`[帧]` 汇总、`[屏]`、`[打卡]`、`[保温]` |
| **二档：逐帧/逐事件** | `debug.trace`（**默认关**） | 每帧或每次事件一行（几十~几百行/秒）| `[悬停拍]`、`[闸]` 指针位移、`[键账]`、`[卡变]`、`[对位]`、`[窗框]` |
| **三档：重型（会改变被测物）** | **各自的开关**（默认关，开机自报）| 明显 | `screenProbe`、`dumpSources`、`hzProbe` |

**规矩**：

1. 加量尺前先问："它会不会落到热路径（每帧/每次按键/每次指针移动）？"
   —— 会 ⇒ 必须走 `debug.trace` 二档，**默认关**；
2. 会**写盘 / 读屏幕像素 / 另开窗口 / 改变行为**的量尺 ⇒ **三档**，必须：
   有自己的键、默认关、写进 `DebugFlags.heavySwitches`（含代价）、用完关掉；
3. **量具不得与被测路径共享资源**（事故①：探针自己产出长帧）；
4. 加量尺的同时想好"**看完怎么关**"，别把它留给下一轮 ⇒ 三档开关会被开机自报抓住。

## 看日志的一条硬规矩

**必须按时间戳排序再看**。日志有多路写入者（主线程 + 池队列 + 后台枚举 + 事件 tap），
`grep` 出来的行序**不等于时间序** ✗ —— 我第一次读这次事故就被交错顺序骗了，
把长帧赖到了"面板收场"上（错的），排序后才看清它紧贴"hover 换 App"。

```bash
# 取某个进程时刻窗口内的**按时间排序**的现场
awk 'match($0,/\[ *([0-9]+)ms\]/){t=substr($0,RSTART+1,RLENGTH-2)+0; if(t>=207230&&t<=207310) print t"\t"$0}' \
  ~/Library/Logs/Glance/trace.log | sort -n | cut -f2-
```
